# MATLAB tests

The test suites check the implementation. They do not regenerate expected results while running.

| Location | Purpose |
|---|---|
| `suites/` | Executable `s_test_suite_*.m` scripts |
| `helpers/` | Case generation, solver-output checking and failure reports |
| `+imrtest/` | Frozen expected values and independent observations, exposed as `imrtest.*` |
| `reference/` | Approved golden simulation histories, one file per solver mode; currently absent |
| `imr_test_setup.m` | One-session path setup for tests and source |

## Run a suite

From the checkout root, in a shell with MATLAB on its path:

```bash
cd tests
matlab -batch "imr_test_setup; s_test_suite_settings"
```

In an interactive MATLAB session, open `tests/`, call `imr_test_setup` once, then run suites by name. Setup adds only the required directories, without `genpath`. Suite data and guide paths are resolved from file locations, so they do not depend on the current folder after setup. The normal solver setup, `imr_setup`, leaves test references off the runtime path.

See [all suite commands and coverage](../docs/validation/tests.md). Numerical checks require licensed MATLAB; documentation checks require no MATLAB.

## Three sources of expected results

1. **Analytic identities and limits.** Most suites check properties such as equilibrium, derivative consistency or pressure balance without stored trajectories.
2. **Independent frozen data.** `imrtest.default_physics()` preserves historical defaults; optional material references supply independent predictions and observations. These MATLAB literals are maintained separately from the implementation and are not generated by the suites or baseline generator. Optional material references and suites are included only in distributions that support them.
3. **Golden simulation histories.** `s_test_suite_regression` reads approved `reference/<mode>.mat` files. `toolchain/s_generate_references.m` creates that specific format. It refuses to replace existing files unless `overwrite = true` and writes nothing unless every simulation case succeeds. Regeneration changes the expected answers and requires a deliberate review; it is never part of an ordinary test run.

The golden histories are currently absent and will be recreated locally in MATLAB. The unused older `.mat` histories have been removed. To create the current keyed baselines, run the generator from the checkout root:

```bash
cd toolchain
matlab -batch "s_generate_references"
```

Review the generated results before accepting them as baselines, then run `s_test_suite_regression` after `imr_test_setup`. See [generation safeguards and baseline availability](../docs/validation/regression.md). The independent frozen MATLAB data in `+imrtest/` are retained.
