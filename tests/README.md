# MATLAB tests

The test suites check the implementation. They do not regenerate expected results while running.

| Location | Purpose |
|---|---|
| `suites/` | Executable `s_test_suite_*.m` scripts |
| `helpers/` | Case generation, solver-output checking and failure reports |
| `+imrtest/` | Frozen expected values and independent observations, exposed as `imrtest.*` |
| `reference/` | Approved golden simulation histories, one file per solver mode; currently absent |
| `imr_test_setup.m` | One-session path setup for tests and source |
| `s_run_validation.m` | Editable settings for running suites and/or generating golden data |
| `run_validation.m` | Callable controller used by the script and batch commands |

## One command for all tests

From the checkout root in MATLAB:

```matlab
run('tests/s_run_validation.m');
```

The script defaults to `mode = 'tests'`, `suites = 'all'` and `overwrite = false`. It handles test-path setup, discovers the suites present in this distribution and runs them sequentially in separate function workspaces. Their `clear` statements cannot erase the controller. It restores the path, working folder and warning settings between stages, prints a pass/fail/timing summary and raises an error after any failure. Suite workspaces are isolated within one MATLAB process; CI continues to use a separate process for each suite.

Edit the three settings at the top of the script, or use the callable controller from `tests/`:

```matlab
run_validation;                                      % all tests
run_validation('tests',{'diffmat','solver'});          % selected suites
run_validation('generate');                          % create missing baselines
run_validation('generate-and-test');                 % prechecks, generation, regression
run_validation('generate-and-test','all',true);       % deliberately replace baselines
```

| Mode | Actions |
|---|---|
| `tests` | All available suites or a selected list; continue after failures and never generate data |
| `generate` | Generate all regression baselines; no test suites run |
| `generate-and-test` | Run selected independent suites first, generate only if they all pass, then run regression |

Suite names may be suffixes such as `solver` or full script names such as `s_test_suite_solver`. Duplicate selections run once; unknown or empty selections fail. `generate` requires all suites selected because it always generates the complete regression case set. In `generate-and-test`, selected regression is moved to the final stage and is included even if omitted from the list; at least one independent precheck must be selected. Failed prechecks block generation and regression; failed generation blocks regression. Blocked stages are reported as skipped and the overall command fails.

Missing baselines remain failures in ordinary test mode. Existing files cannot be replaced without explicit `overwrite = true`, which is rejected in test mode. Generation still needs review: regression against freshly generated files checks repeatability, not independent accuracy. Each stage reports elapsed seconds and failure details. The callable controller returns its report struct on success.

For a shell at the checkout root:

```bash
matlab -batch "run('tests/s_run_validation.m')"
matlab -batch "cd tests; run_validation('generate-and-test')"
```

An uncaught final error gives `matlab -batch` a nonzero exit status. The same commands discover the available suites on `water` without editing a material-specific list.

## Run a suite

From the checkout root, in a shell with MATLAB on its path:

```bash
cd tests
matlab -batch "imr_test_setup; s_test_suite_settings"
```

In an interactive MATLAB session, open `tests/`, call `imr_test_setup` once, then run suites by name. Setup adds only the required directories, without `genpath`. Suite data and guide paths are resolved from file locations, so they do not depend on the current folder after setup. The normal solver setup, `imr_setup`, leaves test references off the runtime path.

See [all suite commands and coverage](../docs/validation/tests.md). Numerical checks require licensed MATLAB; documentation checks require no MATLAB.

## Three sources of expected results

1. **Analytic identities and limits.** Most suites check properties such as equilibrium, derivative consistency or pressure balance without stored trajectories.
2. **Independent frozen data.** `imrtest.default_physics()` preserves historical defaults; optional material references supply independent predictions and observations. These MATLAB literals are maintained separately from the implementation and are not generated by the suites or baseline generator. Optional material references and suites are included only in distributions that support them.
3. **Golden simulation histories.** `s_test_suite_regression` reads approved `reference/<mode>.mat` files. The shared `helpers/generate_references.m` creates that specific format, called by the controller and the existing `toolchain/s_generate_references.m` wrapper. It refuses to replace existing files unless `overwrite = true` and publishes nothing unless every simulation case succeeds and reaches its requested times. Regeneration changes the expected answers and requires a deliberate review; it is never part of an ordinary test run.

The golden histories are currently absent and will be recreated locally in MATLAB. The unused older `.mat` histories have been removed. To create the current keyed baselines, run the generator from the checkout root:

```bash
cd toolchain
matlab -batch "s_generate_references"
```

Review the generated results before accepting them as baselines, then run `s_test_suite_regression` after `imr_test_setup`. See [generation safeguards and baseline availability](../docs/validation/regression.md). The independent frozen MATLAB data in `+imrtest/` are retained.
