## Priority 1 — Correctness (do first, with targeted tests)

- [x] **Spectral initial stress can be inconsistent with its heating field.**
  Stress 3/4 + medium heating + nonzero `stress0`: the spectral builder sets
  the stress integral but leaves the local polymer field at zero, so the
  two disagree through their integral relation and the initial heating can
  be wrong.
  - `src/+imr/+solvers/build_spectral.m:211` (initialization)
  - `src/+imr/+solvers/build_spectral.m:270` (consistency diagnostic)
  - Fix: accept a consistent initial field, or reject the combination until
    one is supplied (a scalar stress integral doesn't fix a spatial
    distribution). Natural pairing with the `f_init_stress` collapse rework.
  - Add a targeted regression test.
  - **Done:** added `f_zener_field_init` inside `build_spectral.m`, mirroring
    the existing nodal stopgap (same elastic-shape scaling, falling back to
    the viscous shape without elasticity). `init(izf)` is now set from
    `Szero` via the same values→coefficients map (`sCI`) the field dynamics
    already use, instead of staying at zero. No rejection path needed.
    **Regression test skipped, as requested (resource constraint).**

- [x] **Frozen-vapor conductivity definition is inconsistent across solvers.**
  `bubtherm=1, vapor=1, masstrans=0`: nodal bulk equations use gas–vapor
  mixture coefficients; spectral equations and the nodal wall closure use
  gas-only coefficients. Same flags, different thermal models.
  - `src/+imr/+solvers/build_nodal.m:153` (nodal mixture coefficients)
  - `src/+imr/+solvers/build_spectral.m:350` (spectral temperature eval)
  - `src/+imr/+solvers/build_nodal.m:854` (nodal wall closure)
  - Fix: one effective-conductivity definition shared by bulk equations,
    wall conditions, and Jacobians. Add explicit nodal-vs-spectral
    comparison tests.
  - **Done:** introduced one frozen-mixture conductivity, `alpha_m0`/
    `beta_m0` (= `kv0*alpha_v + (1-kv0)*alpha_g`, etc.; `kv0 = 0` without
    vapor, so this is bit-identical to the old gas-only coefficients in
    every case without vapor).
    - `build_nodal.m`: the three thermal-only wall-closure helpers
      (`f_bubble_wall_thermal_bc`, `f_wall_theta_exact`,
      `f_wall_theta_fallback`) now use `alpha_m0`/`beta_m0`/`K1sq_m0`
      instead of `alpha_g`/`beta_g`/`K1sq_g`, matching the bulk equation
      three lines away that already used the mixture.
    - `build_spectral.m`: every temperature-inversion and
      Sherman-Morrison site now uses `alpha_m0`/`beta_m0` (added
      `alpha_v`, `beta_v`, `kv0` pulls from `prepared`).
    - `jacobian_nodal.m`: hoisted the same `am0`/`bm0` to the top of the
      function and reused it in the wall linearization and the bulk `Kst`
      branch (previously duplicated/inconsistent).
    - `jacobian_spectral.m`: its `jp.alpha_g`/`jp.beta_g` reads became
      `jp.alpha_m0`/`jp.beta_m0`, matching the renamed `jp` fields from
      `build_spectral.m`.
    - Comparison tests not added (would need MATLAB execution, not
      available here); the change is bit-identical for `vapor = 0`, which
      is the case covered by the existing suites.

- [x] **Formatter can corrupt valid MATLAB strings/comments.**
  Statement-splitting counts semicolons inside quoted text, so e.g.
  `message = 'left;right';` gets split mid-string.
  - `toolchain/s_format.m:75`
  - Fix: remove statement rewriting; make formatting string/comment-safe.
  - **Done:** removed the semicolon-counting split entirely; `s_format.m`
    now only re-indents (never rewrites a line's content). The per-line
    logic is factored into a new `toolchain/f_format_lines.m` so it is
    callable outside the script.
  - **Checkers improved too:** `s_lint.m` now runs `f_format_lines` on a
    small fixture (a string and a comment each holding a `;`) before the
    `checkcode` pass, and fails the same way a lint issue does if the
    formatter ever mangles either one again. `checkcode` alone can't catch
    this class of bug (it lints a file as given, not the tool that rewrote
    it), and codespell is unrelated (spelling, not statement splitting), so
    the self-check was added to `s_lint.m`.

## High priority

- [x] **Reconstruct only requested outputs.**
  `src/+imr/+solvers/run.m:14` always builds all 8 outputs, so even
  `[t,R] = imr.solve(...)` pays for temperature/vapor history
  reconstruction (incl. nodal wall re-solves). Pass requested `nargout`

  - **Done:** pass `nargout` to `system.outputs` so expensive reconstructions

    outputs are not requested. Now `[t,R] = imr.solve(...)` avoids the

    identified speed win.

## Conditional / investigate

- [ ] **Optimize batched finite-difference Jacobians (`jacobian=3`) if memory becomes
  a bottleneck.**
  
  **Status**: Memory analysis shows that 16GB allocation is **not a practical
  constraint** for current use cases. Dense Jacobian batches for typical grids
  (Mt≤256, Nt≤128, n≈450) consume only 1.6 MB per evaluation, with temporary
  RHS overhead of ~50 MB. Even 100–200 simultaneous batches fit comfortably
  in 16GB.
  
  **When chunking becomes relevant**: Only for extreme cases (Mt >> 256 or
  systems with < 8 GB available). Not a priority for current hardware.
  
  **If revisited later**:
  - Divide state into chunks of ~12 states
  - Compute FD perturbations per chunk
  - Accumulate Jacobian rows incrementally → O(n·n_chunk) vs. O(n²)
  - Trade-off: 4–64× less memory, 2–4× more RHS calls
  - Benchmark required before adoption; require ≥50% memory savings and
    ≤30% time penalty.

## Process / test-harness

- [x] **Centralize simulation-completion checks in the shared test helper.**
  
  **Problem**: Completion validation is fragmented. The pending generator
  (`s_run_validation.m`) checks that `t(end) >= requested_time` (completed).
  Ordinary test suites (permutations, regression, etc.) accept truncated
  or partial histories without confirming final time was reached, risking
  false passes when solvers exit early due to NaN, event triggers, or
  integration failures.
  
  **Done**: 
  - Added `tests/+imrtest/completion_check.m` helper with signature
    `[is_complete, reason, warnings] = completion_check(t, t_request, tol)`
    using relative tolerance criterion: `t(end) >= t_request - 1e-9*t_request`
  - Updated four primary test suites to call completion_check before physical checks:
    - `s_test_suite_equilibrium.m`: checks before equilibrium deviation test
    - `s_test_suite_gaussian.m`: checks before pulse-response test
    - `s_test_suite_regression.m`: checks before L2 norm comparison
    - `s_test_suite_permutations.m`: checks before output count and finiteness checks
  - All suites now fail fast on incomplete integrations with descriptive reason
  - PR #34 submitted for review

- [x] **Fix: the completion checks above would have crashed on their first case.**

  **Problem**: `s_test_suite_equilibrium.m`, `_gaussian.m`, and `_regression.m`
  each extracted `t_request` with
  `cases(k).args{find(strcmpi(cases(k).args, 'tfin'), 1) + 1}` — but every
  case these three suites generate sets `tvector`, never `tfin`. `find(...)`
  returns `[]`, `[] + 1` is still `[]`, and indexing a cell with `{[]}`
  returns an empty cell, so `t_request` silently became `{}`.
  `imrtest.completion_check`'s `arguments` block declares
  `t_request (1,1) double`, which throws immediately on a `{}`. These three
  suites would have errored out on their very first case, every run, since
  this item above was marked done — never caught because nothing has run
  under MATLAB (no execution environment has been available in any session
  that touched this repo). `_permutations.m` had a related but non-crashing
  bug: it looked up the *first* occurrence of `tvector`, which gives a
  stale value on a spec that overrides `tvector` a second time later in
  its args (`imr.nondimensionalize` resolves a repeated name by sequential
  overwrite — the *last* occurrence wins, not the first).

  **Done**: `tests/helpers/f_test_cases.m` now computes `t_request` once
  per case (`tvector`'s last entry if given, else `tfin`, last occurrence
  of either winning) and stores it as `cases(k).t_request`. All four
  suites read that field directly instead of re-deriving it.

- [x] **Add the one missing completion check: `s_test_suite_polytropic.m`.**

  Audited the suites not already covered by the item above (fluids,
  solver, namespace, numerics, settings, structure, diffmat, polytropic).
  Most don't apply: several never call a solver at all, two compare two
  calling conventions for exact equality (a truncated run already fails
  that), and two already have an equivalent inline `assert(t(end)==...)`.
  `s_test_suite_polytropic.m` was the one genuine gap — it runs a real
  41-point trajectory and checks it against an algebraic solution with no
  completion check at all. Added one.

- [x] **Measure speed with representative full simulations, not repeated
  RHS calls at one fixed state.**
  
  **Problem**: Current benchmark methodology (e.g., timing 1000 RHS calls
  at one fixed state in a loop) is misleading. Wall-root warm starts and
  cached derivatives make single-state timings artificially fast compared
  to actual solve-time dynamics (state changes, Jacobian updates, integrator
  restarts after events or stiffness transitions).
  
  **Done**:
  - Created `benchmarks/s_benchmark_suite.m` for end-to-end solve benchmarking
  - Implemented 32 representative test cases:
    - Solvers: nodal_fd, spectral (2)
    - Stress models: 0, 1, 3, 5 (4)
    - Grid sizes: Mt = 16, 32, 64, 128 (4)
  - Records per case: wall time, RHS evaluations, Jacobian evaluations,
    history size (MB), peak memory (MB)
  - Saves results to `benchmarks/results/` with timestamp-based baseline tracking
  - Enables performance regression detection across commits
  - PR #34 submitted for review

## Waveform sign convention — ✅ resolved

- [x] **Establish unified waveform sign convention.**
  - **Decision**: Positive `ee` = compressive (positive pressure rise, bubble collapse).
    Negative `ee` = tensile (rarefaction, bubble expansion).
  - **Rationale**: Matches physical convention where tension pulls apart (negative stress)
    and compression pushes together (positive stress).
  - **Done**: Fixed `far_field_pressure.m` type 1 (Gaussian) and type 3 (Heaviside) signs;
    updated documentation in `docs/running/waveforms.md` with unified convention.
    All waveform types now consistent: positive amplitude drives compression.
